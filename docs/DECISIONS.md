# Decisions log

1. **Choose Faultline.** A decision can be useful without a costly generative model. The distinguishing interaction is finding the nearest assumption change that overturns the result.
2. **Design first in Figma.** The editable Figma file predates application implementation. It contains color tokens, type styles, button variants, a desktop workbench, mobile view, notebook, account screen, and state/copy specimens. A first screenshot revealed nested-frame clipping; frame heights were repaired and checked again.
3. **Use Canva for a real asset.** The app uses Canva-generated media `MAHYGAQTn8w`, saved from the connector's supplied 200px image. It is adequate for the small navigation logo; it is not a vector brand master. No claim of hand-drawn vector branding.
4. **Use the Writing Style fallback honestly.** The skill is available; retrieval tools are not. The skill permits proceeding without a retrieved match. Copy follows the brief and direct language, with explicit method limits.
5. **Keep the app local.** No hosting or paid project was requested. Existing cloud Supabase projects were inspected and found paused; none was resumed, altered, or reused. The backend setup targets a dedicated local Supabase project.
6. **Make browser storage a real mode.** The product remains usable with no account configuration. Browser mode is clearly labeled and is not described as cloud sync. Signing in switches to a separate account notebook; a browser decision can be saved as a new account copy.
7. **Keep account drafts in memory.** Saves are explicit. Signing out clears the account draft. Auth tokens use Supabase's standard browser session persistence; private decision payloads are not written into the guest draft store while signed in.
8. **Use bounded JSONB.** Each decision is one atomic document. PostgreSQL validates shape, lengths, IDs, bounds, and score completeness. RLS checks ownership; column grants prevent owner reassignment.
9. **Separate weights from scores.** Exact crossover analysis handles weights. An uncertainty flag handles score bounds. Neither claims a chance of success.
10. **No simulation needed.** Weighted scores are affine in one varied weight, so the crossover can be solved directly. Tests check ties, endpoints, dominance, and generated cases.
11. **Use optimistic concurrency for accounts.** An update must match the loaded revision and increase it by one. A conflicting version is preserved in memory and can be saved as a copy. localStorage has no transaction-level cross-tab lock; simultaneous browser-only saves can still race.
12. **Keep assets self-contained.** Fonts and logo are bundled, with no runtime CDN dependencies or analytics.
13. **Run only necessary backend services.** The local stack starts PostgreSQL, Auth, PostgREST, and Kong. Studio, realtime, storage, analytics, and edge workers are disabled. A dedicated Docker network defaults published ports to loopback; the actual bindings are checked during verification.
14. **Make Windows setup reproducible.** The supplied WSL installer pins CLI 2.121.0 and checks the official archive hash. The backend terminal keeps WSL alive, and the environment helper writes only the public client key. The original ECR image download was slow; the identical official Docker Hub image digest was checked before using the mirror.
15. **Preserve the exact crossover in the UI.** A criterion-change effect originally reset the scenario to its baseline. The Explore tipping point action now carries the exact crossover through that transition, with a browser regression test checking the tie and unchanged baseline.
16. **Hold WSL open during recovery.** WSL can shut down when its last foreground process exits even while Docker services exist. The startup helper now runs before health checks, waits for PostgreSQL recovery, and renews its keepalive if a first-run download outlasts the initial grace period.
